## 1. Executive summary

CryptoScan is a **cryptographic discovery, inventory, and compliance platform**: it scans source code (and, conditionally, containers, TLS endpoints, cloud accounts, OT devices) for cryptographic usage, hashes every finding into a tamper-evident evidence chain, normalizes algorithms to NIST/IANA names, evaluates versioned YAML policy rules, detects drift against approved baselines, and serves everything through a FastAPI REST API + dashboard. Its foundational principle is explicit and consistently enforced in the code: **deterministic evidence first, AI assists never decides compliance**.

**Current verdict: this is a working product for its Part 1 + much of Parts 2–3 scope — not a skeleton.** The previous analysis (2026-08-24, `ANALYSIS.md`) assessed ~0% working E2E; that has changed substantially:

## 4. What's genuinely good

- **The core loop is real and deterministic.** Scan → hash-chain → normalize → policy → drift → CBOM all execute correctly, verified live, with `make test` green and per-service isolation that avoids the `tests` package clash.
- **Evidence integrity is the strongest part.** Per-finding content hash, per-scan chain hash, verification CLI + API endpoint, signed evidence packs (`verify_pack.py` with HMAC secret).
- **Policy as data, not code.** 27 versioned YAML rules with a schema, effective dates, standard references (NIST SP 800-131A, CNSA, FIPS, PCI-DSS, HIPAA), and remediation text. Exactly matches the "no AI decides compliance" principle.
- **Safe-by-default live scanning.** Network/TLS/cloud/container live actions are gated behind `CRYPTOSCAN_*_LIVE=0`; mocks in dev/test.
- **Production hardening exists and fails closed.** `validate_runtime_settings` refuses demo secret keys, plaintext admin passwords, SQLite, wildcard CORS, and dev login when `ENVIRONMENT=production`. Login lockout with constant-time compares. Security headers + trusted-host middleware.
- **Sensible deployment story.** Non-empty Dockerfiles for api/worker/nginx/dashboard/scanner, dev + prod compose overlays (resource limits, log rotation, no published DB ports in prod), Postgres/Redis/Neo4j with healthchecks, host ports offset to avoid collisions.
- **Excellent docs.** 72 non-empty markdown docs: architecture designs (11), admin guides (17), user guides (21), 13 ADRs — they match the implementation unusually well.

## 5. Gaps, bugs, and sharp edges (found live)

### Blocking-ish
1. **CI is a facade.** All 4 workflow files (`.github/workflows/*.yml`) are **0 bytes**. Every push runs zero checks despite Dependabot being configured (and referencing workflows that don't exist). This is the single highest-leverage fix: a workflow that runs the same `make test` loop I ran (23 suites, ~17s total).
2. **The React dashboard is a mirage.** `services/dashboard/src/**` (68 .ts/.tsx files: pages, hooks, stores, tests) is 100% empty; `package.json` "build" just copies `index.html`. The real UI is a single 1,313-line hand-rolled SPA — functional but unmaintainable at scale, with Google-Fonts CDN dependency (breaks air-gapped installs).
3. **Empty `poetry.lock` files** in 9 services while `pyproject.toml` exists — dependency resolution is actually done by the root `requirements.txt`. Confusing dual packaging; pick one.

### Behavioral quirks (verified)
4. **`GET /api/v1/findings?scan_id=…` silently ignores `scan_id`** and returns findings across *all* scans (the correct route is `/scans/{scan_id}/findings`). FastAPI doesn't reject unknown query params, so callers get quietly wrong data. Fix: add the parameter or 422 on unknowns.
5. **Drift blind spot by design:** a *new occurrence* of an already-present (weak) algorithm — e.g. a second MD5 call in a new function — is **not** flagged, because NEW is suppressed when the semantic signature `algo|key|mode|purpose` already exists in the baseline. Adding MD5 to a file that already had MD5 produced zero events. Defensible noise-reduction, but it under-reports weak-crypto spread; worth a policy-level "weak-algo count increase" event.
6. **Two parallel drift stacks**: `drift/core/comparator.py` (CryptoInventory/DriftEvent, richer, "Month 3+") and `drift/core/detector.py` (DriftChange, used by the pipeline). Both maintained; risk of divergence.
7. **Duplicate parsers**: `java_parser.py` vs `java_ast.py`, `javascript_parser.py` vs `js_ts_parser.py` — overlapping implementations; unclear which is canonical without reading the registry.
8. `git` metadata extraction logs a warning on every local scan (`cannot_extract_git_metadata`) — noise, plus a recurring `refusing_to_delete_workspace_outside_base` warning in seed/inline mode.

### Scale/ops
9. **Auth is single-user.** One admin (env-configured, optional hash), roles hardcoded `["admin"]`, in-memory lockout state (reset per process), HMAC tokens without revocation store. Fine for a security tool's MVP; not multi-tenant.
10. **Worker is sync** (`8-stage scan pipeline (sync)` docstring, now ~13 stages) — one scan at a time per process; Redis queue exists but no concurrency fan-out.
11. **Neo4j optional but code assumes graceful skip** — verified the API boots without it; good. But `k8s/` contains only Neo4j manifests — there is no K8s deployment for the app itself. Grafana dashboard JSON is empty; Prometheus scrape config exists.
12. **Repo hygiene**: `logic-1..5.md` (~900 KB) + stale `ANALYSIS.md` live at root; `.editorconfig`/`CODEOWNERS` fine; `alembic.ini`/`script.py.mako` empty (migrations run via `scripts/run_migrations.sh` instead); 141 empty files total masquerade as features in the tree.

## 7. Security posture (as a security product, it should be held to its own standard)

**Good:** fail-closed production validation (demo secret/admin/SQLite/CORS refused), constant-time credential compare + lockout, HMAC-signed session tokens, security headers, trusted-host middleware, webhook HMAC verification, evidence packs with explicit secrets, live-scan kill switches, docs on IAM least-privilege for AWS/Azure/GCP.

**Needs work:** single admin user / no RBAC despite `roles` field; token revocation & rotation absent; lockout state in-process only (trivially bypassed by restart); dashboard pulls Google Fonts from CDN; default dev credentials are documented in the README (acceptable for dev, and prod refuses them); no rate limiting on API endpoints; CI absence (§5.1) means no enforced lint/type/test gates (`ruff` is a dependency but nothing runs it).

## 8. Prioritized recommendations

1. **Write the CI workflows** (30 min, highest ROI): one job running the exact `make test` loop + `ruff check`; a Docker build job; keep Dependabot. Optionally a job that runs `seed_demo.py` as an E2E smoke test — I've proven it works in <2s.
2. **Delete or commit to the dashboard decision**: remove the 68 empty React files (or actually build them). Rename the vanilla SPA clearly as the UI of record; vendor the fonts or drop them for air-gap support.
3. **Fix the `findings?scan_id` filter** (add scan_id to `list_all` or reject unknown query params globally via middleware).
4. **Add a weak-algorithm-spread drift event** when the count of a weak semantic signature grows vs. baseline.
5. **Consolidate duplicates**: one drift stack, one Java parser, one JS parser; delete the unbuildable `jdt/` Java or wire it behind a feature flag with a build.
6. **Pick one packaging system** (root `requirements.txt` is the real one — remove empty poetry.locks or generate real locks).
7. **Multi-user auth** (users table exists in migrations? extend it), token revocation, persistent lockout.
8. **Worker concurrency**: async or multi-process fan-out for parallel scans; pipeline stage list is already clean enough to parallelize per-scan.
9. **Ship K8s manifests for the app** (only Neo4j exists) or drop the `k8s/` dir; populate the Grafana dashboard JSON or remove it.
10. **Housekeeping**: move `logic-*.md` into `docs/specs/`, archive the stale `ANALYSIS.md`, sweep remaining empty files.

## 9. Bottom line

The distance traveled since the 2026-08-24 analysis is large: from "61% empty files, 0% E2E" to **a deterministic, test-covered, live-verified crypto-compliance pipeline** where the hardest parts (evidence chain, policy-as-data, drift, CBOM, multi-language scanning) demonstrably work. The remaining risk is concentrated not in the core but in **delivery and durability**: no CI, a facade React app, duplicated subsystems, and single-user auth. Items 1–4 above would move this from "works on my machine" to "defensible as a production security tool."
