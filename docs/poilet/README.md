# CryptoScan pilot and first-customer playbook

**Folder name:** `docs/poilet/` (kept exactly as requested; the product
language elsewhere uses **pilot**).

**Document status:** proposed operating plan. These documents are not executed
contracts, customer references, certifications, regulator approvals, or proof of
market demand. Any customer, partner, regulator, accelerator, or government
relationship must be separately confirmed in writing.

## What this folder is for

This folder turns CryptoScan from a product repository into a controlled path to:

1. identify the right pilot markets and buyer personas in the order Dubai/UAE,
   Saudi Arabia, the United States, the European Union, and India;
2. explain the product honestly to a technical decision-maker;
3. run a supervised real-system pilot without over-collecting data or claiming
   production approval;
4. hire only the people needed to deliver the first five customers; and
5. create a repeatable, evidence-based sales process.

## Standing product boundary

CryptoScan is currently positioned for a **supervised pilot / pre-production
evaluation**. It is not an unattended regulated-production claim. A pilot must
state:

- exact sources and systems in scope;
- deployment location and data boundary;
- read-only versus active collection;
- retention and deletion date;
- named customer security owner and vendor delivery owner;
- success measures and a stop condition; and
- what the results do not prove.

Static binary analysis is metadata-only and bounded. It does not prove runtime
execution, exploitability, signer trust, complete estate coverage, or live network
exposure. Binary-derived NBOM candidates remain static candidates until an
separately authorized network scan provides corroboration.

## How to use the plan

Do not send all documents to a prospect. Internally, use the full folder as the
operating system. Externally, send only:

1. a one-page problem statement;
2. a scope-specific pilot charter;
3. a sanitized architecture/data-flow diagram;
4. the security and data-processing answers that are actually evidenced; and
5. a short, customer-specific pilot proposal.

Never send a document that says a customer, regulator, bank, accelerator, or
standard has approved CryptoScan unless that approval is real, current, and
available as evidence.

## Source and contact hygiene

Public contact routes change. Before outreach, open the official page, verify the
address, confirm that the programme is still accepting applications, and record
the access date in the CRM. Do not scrape personal email addresses, purchase
lists, or contact an employee through a private channel without permission.
The contact map uses role-based routes and official programme inboxes wherever
possible.
