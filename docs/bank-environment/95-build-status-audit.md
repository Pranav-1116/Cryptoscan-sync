# 95 — Build status, measured

Generated by `python scripts/audit_build_status.py --markdown docs/bank-environment/95-build-status-audit.md`. Re-run it after any change; a status that is typed by hand rots within a week.

## What this measures, and what it refuses to

A status report that says "90% complete" is a feeling. These are the only four things this script can actually see, and each is stated with its ceiling:

* **Surface without a screen is the real gap.** The engines exist; the console over them often does not. That is why the estate/twin work (59 endpoints, 34 with a screen) is a small share of 1,185 and why "it is all still partial" is a defensible reading of this table.
* **Four things cannot be measured from source at all**, and are therefore absent from every number below: correctness against a real bank estate, vendor hardware behaviour (HSM firmware, ADC images), whether a screen is *usable*, and whether an approval workflow matches a regulator's expectation. Those need a deployment and an auditor, not a script.
* **Test references are counted, not judged.** A route reached once by a smoke call counts the same as one with twenty behavioural tests.
